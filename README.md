# מלאי חטיבה 55: מדריך התקנה

מערכת לניהול מלאי לוג״ת וציוד צ׳: דף ראשי, מלאי חופשי, קבלות, דוח צ׳ ומתאר ציוד לכל יחידה. לחטיבה יש בנוסף השאלות מיחידות, מתארים וקיטים. הכניסה היא עם חשבון Google. כל משתמש משויך ליחידה או לבעל תפקיד, ויכול לחתום רק בשם היחידה שלו.

ההתקנה לוקחת בערך 20 דקות, פעם אחת. **זו מערכת נפרדת לגמרי מהאפליקציות האחרות**: פרויקט Firebase חדש ומאגר GitHub חדש.

> **אבטחת מידע.** Firebase ו־GitHub Pages הם שירותים ציבוריים. אין להזין למערכת מספרי צ׳ אמיתיים, מיקומי מצפינים, תקופות הצפנה או כל מידע מסווג אחר בלי אישור של אבטחת מידע ביחידה. להדגמה, עם נתוני הדמו, אין בעיה.

## מה יש בתיקייה

| קובץ | מה זה |
|---|---|
| `index.html` | האפליקציה עצמה |
| `config.js` | פרטי החיבור ל־Firebase, ממלאים בשלב 3 |
| `firestore.rules` | כללי האבטחה, מדביקים ב־Firebase בשלב 2 |
| `seed.js` | מבנה החטיבה, קטלוג הציוד ונתוני הדמו לייבוא הראשון |
| `README.md` | המדריך הזה |

## שלב 1: פרויקט Firebase חדש

1. נכנסים ל־[console.firebase.google.com](https://console.firebase.google.com) עם kfirdaabul1@gmail.com.
2. **Create a project**, שם: `inventory-55`. מבטלים Google Analytics ולוחצים **Create**.
3. **Build ← Authentication ← Get started**.
4. בלשונית **Sign-in method** בוחרים **Google**, **Enable**, בוחרים מייל תמיכה ו־**Save**.

## שלב 2: מסד הנתונים וכללי האבטחה

1. **Build ← Firestore Database ← Create database**.
2. מיקום: **eur3 (europe-west)**. מצב: **Start in production mode**. **Create**.
3. בלשונית **Rules** מוחקים הכל ומדביקים את כל התוכן של `firestore.rules`.
4. **Publish**.

## שלב 3: מחברים את האפליקציה

1. גלגל השיניים ליד **Project Overview ← Project settings**.
2. ב־**Your apps** לוחצים על `</>` (Web), נותנים שם ו־**Register app**.
3. מעתיקים את הערכים מ־`firebaseConfig` לקובץ `config.js`, במקום כל ה־`PASTE`.
4. שומרים.

> הערכים האלה לא סודיים. מה שמגן על הנתונים זה כללי האבטחה משלב 2.

## שלב 4: מעלים לאוויר (GitHub Pages, בחינם)

1. ב־[github.com](https://github.com): **New repository**, שם: `inventory-55`, **Public**, **Create repository**.
2. **uploading an existing file**, גוררים את חמשת הקבצים, **Commit changes**.
3. **Settings ← Pages**: Source **Deploy from a branch**, ענף `main`, תיקייה `/ (root)`, **Save**.
4. אחרי דקה־שתיים מופיעה הכתובת, למשל `https://USERNAME.github.io/inventory-55/`.

> המאגר ציבורי, ולכן כל אחד יכול לראות את הקוד ואת `seed.js`. בגלל זה `seed.js` מכיל רק נתוני דמו. הנתונים האמיתיים נשמרים ב־Firebase, ורק משתמשים מורשים יכולים לגשת אליהם.

## שלב 5: מאשרים את הכתובת ב־Firebase

1. **Authentication ← Settings ← Authorized domains ← Add domain**.
2. מוסיפים `USERNAME.github.io` (בלי `https://` ובלי `/inventory-55`).

## שלב 6: כניסה ראשונה והקמה

1. פותחים את הכתובת ונכנסים עם Google (kfirdaabul1@gmail.com). אתה בעל המערכת ורואה הכל.
2. במסך **הקמה ראשונית** בוחרים:
   - **ייבוא המבנה**: 42 יחידות ובעלי תפקיד, 21 סוגי ציוד ו־2 קיטים, בלי ציוד.
   - **ייבוא עם נתוני דמו**: כמו באב־הטיפוס, כולל פריטי צ׳, מלאי, קבלות והשאלה לדוגמה.
3. נכנסים לתפריט ← **הרשאות** ומוסיפים את מנהלי ההרשאות (שלב 7).

## שלב 7: משתמשים והרשאות

כל משתמש מתווסף לפי כתובת ה־Google שלו, בעמוד **הרשאות**. בטבלה למעלה בוחרים יחידה ואז ממלאים מייל, שם ותפקיד.

| הרשאה | מה היא מאפשרת |
|---|---|
| **מורשה חתימה** | לקבל, לנפק, לזכות, לאשר העברות ולבצע אישור שבועי בשם היחידה |
| **מנהל הרשאות** | להוסיף ולהסיר משתמשים. בחטיבה: בכל החטיבה. בגדוד: רק בגדוד ובפלוגות שלו |
| **קליטת אמצעים** | רק בחטיבה: לקלוט ציוד והשאלות מבחוץ |

סדר מומלץ:
1. בעמוד ההרשאות של **חטיבה 55** מוסיפים את קצין הקשר וקצין הלוגיסטיקה החטיבתיים, עם **מנהל הרשאות** ו**קליטת אמצעים**.
2. בוחרים כל גדוד בטבלה ומוסיפים לו מנהל הרשאות, למשל קצין הקשר הגדודי.
3. מנהל ההרשאות של כל גדוד נכנס בעצמו ומוסיף את הפלוגות, החפ״קים ובעלי התפקיד.

משתמש שנכנס ועוד לא נוסף רואה הודעה עם כתובת המייל שלו, כדי שיוכל לשלוח אותה למנהל ההרשאות.

**מה כל משתמש רואה.** משתמש חטיבתי רואה את כל החטיבה, משתמש גדודי רואה את הגדוד שלו ואת הפלוגות שלו, ומשתמש פלוגתי רואה את הפלוגה שלו. חתימה אפשרית רק בשם היחידה שהמשתמש משויך אליה.

> **מגבלה בגרסה הזו.** ההפרדה בין גדודים נאכפת במסך. במסד הנתונים, כללי האבטחה אוכפים מי רשאי לכתוב (מורשה חתימה, מנהל הרשאות, קליטה), אבל כל משתמש מורשה יכול טכנית לקרוא את נתוני כל החטיבה. הפרדת קריאה מלאה בין גדודים דורשת שכבת שרת (Cloud Functions, מסלול Blaze), ואפשר להוסיף אותה בהמשך.
